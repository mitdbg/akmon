# Design fixtures: six mock deployments

These six JSON files are the only data the operator console's redesign mocks
read. They exist so the design is judged against six deployments at once
instead of one, and so the operator can switch between them while judging it.
Four mocks were rejected in September 2026; each had been drawn against a
single deployment, so scale, emptiness and a broken runtime never touched them.

Nothing here is live data. Nothing here is written by the console. They are
generated, not edited.

```
node scripts/operator-ui-design/generate-fixtures.mjs           # write
node scripts/operator-ui-design/generate-fixtures.mjs --check   # verify
```

`--check` regenerates every file and fails on any byte difference, so a hand
edit or a generator that stopped being deterministic is a failure rather than a
quiet drift between the fixture the tests read and the one the mocks were drawn
against. The generator is seeded; the clock is pinned to
`2026-09-18T09:00:00.000Z` so two captures of the same fixture are identical.

## The file

Each file is one object:

| Key | What it is |
|---|---|
| `name` | The fixture's name, and the switcher's label |
| `purpose` | What this deployment is for, in one sentence |
| `clock` | The moment every age and timestamp in it was computed against |
| `stories` | The user stories from `redesign-requirements-v2.md` section 1a it serves |
| `edge_cases` | What it carries that the others do not |
| `expect` | The counts `design/fixtures.test.ts` asserts after loading it |
| `reads` | `"<route>?<sorted params>" -> payload`, exactly as the console reads them |

A read's key is its route plus the parameters that are neither null nor
`refresh`, sorted by name. `design/fixtureClient.ts` builds the same key and
**refuses** a read the fixture does not define, naming the fixture and the key.
A fixture client that answered `{}` would render a healthy-looking blank page
for a read nobody wrote, and the mock would be approved on a lie.

## The six

### `archiv3-small` — the real Archiv3 shape

Five sources, no enrichers, no views, 2,605 records in six types, four
relationship types. One published version five days old, then five blocked
attempts; reads still serve the published one. Runtime queue evidence is
unavailable and says so.

Stories: S1, S2, S4, S9, S10.

- The latest attempt is blocked while reads serve an older version (S1).
- One source failed with a two-line recorded error; Updates, the Sources rail
  and Home's Needs attention must all show the same text (S2).
- No cadence is declared anywhere, so the Sources "next due" column must be
  **absent**, not blank (S9).
- `document:release-plan` names a file its corpus root no longer holds: the
  artifact read answers `file_missing`, the third way an original can be
  absent beside "not retained" and "refused by policy".
- The source read returns **11 rows for 5 sources** — each of the first three
  also appears under its runtime key. Sources must show five. This is the
  duplicate-row defect the view fixes by design.
- Runtime queue evidence is unavailable, which must not read as an empty queue.

### `workspace-mixed` — every producer kind and state

Thirty sources, three enrichers, four views. Eighteen published versions, three
blocked attempts, one attempt running now.

Stories: S7, S9, S11, S12, S14, S15, S16, S17, S18, S19, S21.

- Every producer state in one table: updated, failed, running, never run,
  excluded (S18, S21).
- An enricher **withheld** with a stated reason, and a view whose build failed
  with a four-line error (S19).
- Six producers contributed **zero** records in the selected version, which must
  show as `0`, not blank (S7).
- A 73-character source name that must truncate without hiding its tail.
- A cadence on half the sources, so "next due" is populated on some rows and
  empty on others (S9).
- `document:handbook` has a policy-hidden field; Fields must say "hidden" and
  name `nomos.contact_details`, and Raw must show it masked, not absent (S15).
- `document:handbook` has a **retained payload**; `person:riley` has one the
  policy **refuses**, with the reason stated. The Raw tab needs both (S14).
  The same policy refuses `person:riley`'s original file: an artifact read
  is governed by the source policy that gates the retained payload, so
  serving a file never bypasses the masking applied to attributes.
- Real files under `artifacts/`, generated byte for byte by
  `lib/artifacts.mjs`: `paper:okg-2026` is a two-page PDF with three
  `document_chunk` records linked by `contains`; `document:handbook` a
  Markdown document; `file:src/main.rs` a Rust file; `document:status-page`
  an HTML page carrying an inline and a remote script that the Content
  tab's frame must neither run nor fetch; `document:diagram` a PNG.
  `session:sess-1`'s retained payload is 350 KB, past the raw read's
  256 KB inline limit. The other retained payloads are written under
  `payloads/` so the raw read's `url` resolves in the harness.
- Eighteen published versions, so the version picker has something to switch
  between (S16).
- Forty records that match `ingest` (issues, decisions and runbooks from four
  sources, updated over fourteen months), read on two pages, with one type
  checked, sorted newest, within the past month, and from one source; and
  one query, `zzz-no-such-record`, that matches nothing. The results page's
  paging, rail and empty state are drawn from these.

### `scale-200` — nothing on Home may grow

220 sources from a code-repository expansion, 214 record types, 600
relationship types, 4,800 attempts over a year, nine failed sources.

Stories: S6, S8, S13.

- Home must render the same elements here as at five sources; only the numbers
  differ (S8).
- 4,800 attempts across a year give the chart a real rhythm and the Updates
  read a reason to have a cursor (S6).
- A blocked attempt carries a **forty-line** recorded error, which Updates shows
  verbatim one level down.
- `commit:9a1c02e` has **500 relationships** across six relationship types, 400
  outgoing and 100 incoming, capped at 100 per direction. The Related tab must
  state the cap and how many rows it omitted (S13). It carries a
  `citation_url` to github.com at its sha, and `file:src/main.rs` the Rust
  artifact.
- 600 relationship types, so Home's relationship list must bound itself.

### `empty` — configured, never published

Three sources, all never run. No version, no records, no relationship types.

Stories: S20.

- There is no published version, so every "version read from" line has nothing
  to name (S20).
- Three sources are configured and none of them is shown as failed.
- Explore must say there is nothing to search yet. The fixture **refuses** the
  record-search read, so a view that issues it anyway fails loudly instead of
  rendering an empty result list.

### `broken-runtime` — the system is wrong, not the data

Four sources, all succeeded. One view failed. The last completed attempt was
blocked on a publication check, and one attempt has been running for six hours.

Stories: S2, S3.

- No worker has reported for nearly six hours; 37 jobs are in the dead-letter
  queue; 2,566 jobs are queued and not draining. Home must list these runtime
  checks **separately** from attempts (S3).
- The blocked attempt stopped on a publication invariant, not on a source, and
  names no producer — the case that distinguishes a data failure from a system
  one (S3).
- An attempt has been running for six hours and must read as running, not
  failed.
- A view whose last run timed out after 300,000 ms, with the error verbatim.

### `all-clear` — nothing is wrong

Eight sources, one enricher, one view, all updated. Fifteen consecutive
published attempts. Empty queue, reporting worker, no failing check.

Stories: S5.

- Home's count strip reads all-healthy and Needs attention must be **one
  sentence carrying the fact that makes it so**, with no red anywhere (S5).
- The queue is empty and the worker is reporting, so the runtime check list is
  empty rather than absent — an empty list and a missing read are different
  things and must look different.
- Every producer is "updated", so the Sources count strip has one populated
  bucket.

## Reads that the backend does not serve yet

Seven reads in these fixtures have no route or field today. They are the backend changes
listed in `scripts/operator-ui-design/redesign-requirements-v2.md` section 10, and each one
is marked `"gap"` in its payload so nobody mistakes the fixture for evidence
that the read exists.

| Read | Gap |
|---|---|
| `/viz/api/console/attempts?range=<n>d` | Attempts by outcome over a window (gap 3) |
| `generations[].stopped_stage`, `.stopped_producer`, `.error_text` | An attempt records neither the stage nor the producer it stopped on (gap 1) |
| `generations[].next_cursor` | The attempts read is capped at 50 with no cursor (gap 5) |
| `records/detail.provenance`, `.chunks`, `related.outgoing_total`, `related.incoming_total`, `related.by_relationship` | Record detail returns no fact log (with the producer's kind and the attempt that wrote each entry), no chunk texts, and states its cap without saying how many rows it omitted or how many per relationship type (gap 4) |
| `records/search` parameters `source`, `sort` (`newest`, `oldest`) and `since` (`month`, `year`, or a date), the `applied` block echoing the filters honoured, `facets` (`types`, `sources`, `with_artifact`) over every match, and `updated`, `related_count`, `citation_url`, `has_artifact` per hit | The live read filters by `type` only, returns `total_count` and `next_offset`, and carries none of these; the results page names any filter the read did not apply |
| `/viz/api/console/records/artifact?id=&version=` | Whether the original file exists, its media type, byte count, SHA-256 and the URL its bytes are served at; or `exists: false` with `reason` `not_retained`, `policy_refused` (with the policy) or `file_missing`, and a detail sentence (gap 4). Governed by the same source policy as the retained payload |
| `/viz/api/console/records/raw?id=&version=` | The stored row, the stored edge rows capped at 200 with `edge_total`, and the retained payload as `{sha256, byte_count, inline, head, line_count, url}`: `inline` up to 256 KB, else the first 200 lines in `head`; or `refusal` `{reason, policy, detail}` with the row and edges still served (gap 4) |

`/viz/api/console/ontology-rollup` is a fifth: the composer
`src/okg/substrate/console_views/ontology_rollup_read.py` exists but no route
serves it, so Home's relationship-type counts have no reader today.

One read is deliberately **not** collapsed: `/viz/api/console/sources` returns
one row per registry name **and** one per runtime key, the way the live read
does. Collapsing it in the fixture would hide the defect the Sources view exists
to fix (gap 2).
